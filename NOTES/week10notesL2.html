Three methods

THREE ERROR DETECTION METHODS

PARITY CHECK

Counts the number of 1s.

CHECKSUM

Calculates and compares a value.

ECHO CHECK

Sends received data back to the sender.

All three help identify possible transmission errors.

Part 1 · Parity check

WHAT IS A PARITY CHECK?

A parity check uses an extra bit, the parity bit, to check whether data may contain an error.

EVEN PARITY

Total number of 1s must be even.

ODD PARITY

Total number of 1s must be odd.

Odd and even parity

COUNT ONLY THE 1s

ODD PARITY
Tap to check
Three 1s = odd
EVEN PARITY
Tap to check
Two 1s = even

Remember: count only the 1s, not the 0s.

Part 1 · Parity check

HOW DOES IT DETECT AN ERROR?

  1. The sender adds a parity bit.
  2. The data is transmitted.
  3. The receiver counts the 1s.
  4. The receiver checks the parity rule.
Even parity: the receiver counts three 1s. What does this mean?
Tap to check
Three is odd, so an error is indicated.
Important limitation

PARITY CANNOT DETECT EVERY ERROR

Original · two 1s
Received · two 1s
Both have even parity. Was the error detected?
Tap to check
No. The data changed, but the number of 1s stayed the same. Some errors pass a parity check undetected.
Part 2 · Checksum

WHAT IS A CHECKSUM?

A checksum is a value calculated from the data before transmission.

The sender sends the data together with the checksum.

The receiver calculates a new checksum and compares the two values.

Part 3 · Echo check

WHAT IS AN ECHO CHECK?

The receiver sends the received data back to the sender.

The sender compares it with the original data.

Match?
Tap to check
No error is indicated.
Mismatch?
Tap to check
The data is different.
