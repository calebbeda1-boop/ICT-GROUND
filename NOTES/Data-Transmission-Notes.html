2.1 Types and methods of data transmission

Data packets and how they are structured and switched across a network, serial vs parallel, simplex/half-duplex/full-duplex, choosing a method, and the USB interface.

1. The structure of a data packet

Syllabus objectives 1(a) and 1(b)

A file can be very large. If a whole file were sent across a network as one single block, it would tie up the connection for a long time, and a single fault anywhere in it would ruin the whole transmission. Instead, before it is transmitted, a file is broken down into packets: small, separate units of data that are sent one at a time and reassembled at the other end.

Breaking data into packets also lets many devices share the same network fairly, and if one packet is damaged or lost, only that small packet has to be sent again, not the whole file.

The three parts of a packet

Every packet has exactly three parts, always in this order: a header, a payload, and a trailer.

PartWhat it containsWhy it is needed
HeaderThe destination address, the packet number, and the originator’s addressTells the network where the packet is going, lets the packets be put back in order, and lets the receiver ask for a resend
PayloadThe actual data being sentThis is the whole point of the packet: a small slice of the file or message
TrailerA marker for the end of the packet, and the data used by an error-detection method (such as a checksum)Lets the receiver know the packet has ended, and lets it check whether the payload arrived correctly

What is in the header, in detail

  • Destination address — usually an IP address. It is the address of the device the packet is being sent to; without it, the network would not know where to deliver the packet.
  • Packet number — identifies this packet’s position in the file. Packets do not always arrive in the order they were sent (you will see why in Section 2), so the receiving device uses the packet number to put them back in the correct order.
  • Originator’s address — the address of the device the packet was sent from. It is not essential for delivery, but it lets the receiver (or the network) trace where a packet came from, and lets it ask that device to resend a packet if one is missing or damaged.
Remember

Packet = header + payload + trailer. The header holds exactly three things: destination address, packet number, originator’s address. Cambridge awards marks for these named items — “sender’s name” or “file name” will not earn the mark.

Click each part of the packet to see what it contains.

Example: one packet of a photo upload

A phone is uploading a photo to a cloud storage service. The photo has been split into 40 packets. Packet number 17 of that upload might contain:

SectionContents in this packet
HeaderDestination address: the address of the cloud server · Packet number: 17 · Originator’s address: the address of the phone
PayloadThe 17th slice of the photo’s image data
TrailerAn end-of-packet marker, plus a checksum value used to check this packet for errors

Check yourself (5 questions)

  1. Name the three sections of a data packet, in order.
    Answer
    Header, payload, trailer.
  2. State the three items of information contained in the header.
    Answer
    The destination address, the packet number, and the originator’s address.
  3. Which section of the packet contains the actual data being sent?
    Answer
    The payload.
  4. Give two reasons why data is broken down into packets before it is transmitted.
    Answer
    Any two: a whole large file would take too long / be impractical to send as one block; packets let many devices share the network; if a packet is lost or damaged, only that packet needs to be resent rather than the whole file.
  5. Why is the packet number needed if the originator’s address is already known?
    Answer
    The packet number is used to put the packets back into the correct order when they arrive, since they may not arrive in the order they were sent; the originator’s address is only used to say where a packet came from, not what order it belongs in.

2. Packet switching

Syllabus objective 1(c)

Packet switching is the process of sending packets of data across a network from one device to another. Each packet is transmitted separately, and different packets belonging to the same file can travel by completely different paths.

How it works, step by step

  1. The data is broken down into packets, each with a header, payload and trailer.
  2. Each packet is sent onto the network on its own. There may be several possible pathways between the sender and the receiver, and each packet could take a different route.
  3. A router is the device that controls which pathway a packet takes. At each router the packet reaches, the router looks at the destination address in the header and passes the packet on towards the next router on a suitable path.
  4. Because different packets can take different routes, some paths are longer or busier than others, so the packets may arrive out of order.
  5. Once the last packet has arrived, the receiving device uses the packet numbers in the headers to reorder the packets and rebuild the original file.
  6. If a packet does not arrive, or arrives damaged, the receiving device can use the originator’s address to ask for that one packet to be resent.
Remember

The order matters in an exam answer: split into packets → routers direct each packet, possibly by a different route → packets may arrive out of order → once the last packet arrives, they are reordered using the packet numbers. Leaving out the reordering step is a common way to lose a mark.

Advantages and disadvantages of packet switching

AdvantagesDisadvantages
Packets can avoid busy or broken routes, so the network is used efficiently and data can still get through if part of the network failsPackets may arrive out of order, so time and processing is needed to reorder them
Many devices can share the same network at the same time, since no single dedicated pathway is reserved for one fileA delayed or lost packet has to be requested again, which slows down the overall transmission
If a packet is lost or corrupted, only that packet has to be resent, not the whole fileEach packet carries extra data (the header and trailer), which adds to the total amount of data transmitted
Example: a five-packet journey

A file is split into 5 packets and sent from a laptop to a server. Because of network conditions, packets 1, 3 and 4 travel through router A, while packets 2 and 5 are sent through router B, which is less busy at that moment. Packet 3 arrives first, then 1, then 5, then 4, and packet 2 is delayed and arrives last.

Even though the packets arrived in the order 3, 1, 5, 4, 2, the server does not use them in that order. It waits until packet 2 (the last one) has arrived, then reorders all 5 packets into 1, 2, 3, 4, 5 using the packet numbers stored in each header, and rebuilds the original file.

Check yourself (5 questions)

  1. What is packet switching?
    Answer
    The process of transmitting packets of data separately across a network, where each packet may take a different route to reach the destination.
  2. What is the job of a router in packet switching?
    Answer
    It controls which route/pathway a packet takes across the network, directing it towards its destination address.
  3. Why might packets arrive at their destination out of order?
    Answer
    Because different packets can be sent along different routes, and some routes take longer than others (for example, because they are busier).
  4. How does the receiving device put the packets back into the correct order?
    Answer
    It uses the packet number stored in each packet’s header, once the last packet has arrived.
  5. Give one advantage and one disadvantage of packet switching.
    Answer
    Any one advantage (e.g. packets can avoid busy or broken routes / only a lost packet needs resending / many devices can share the network) and any one disadvantage (e.g. packets may arrive out of order and need reordering / a lost packet must be requested again, causing delay / extra header and trailer data increases the amount transmitted).

3. Serial and parallel data transmission

Syllabus objectives 2(a) and 2(b)

Serial and parallel transmission are about how many wires are used and how many bits are sent at a time.

Serial transmission

In serial transmission, data is sent one bit at a time, one after another, down a single wire.

AdvantagesDisadvantages
Bits arrive in the order they were sent, so there is very little chance the data becomes jumbled (skewed)Slower than parallel transmission, because only one bit moves at a time
Only one wire is needed, so the cable is cheaper to make and to buyExtra bits (a start bit and a stop bit) may need to be sent to mark when the transmission of each unit begins and ends
Only one wire carries the signal, so there is less chance of interference between wires and therefore less chance of an error

Because it is reliable over longer distances, serial transmission is normally used to send data between separate devices, for example between a computer and a printer, or across a network.

Parallel transmission

In parallel transmission, multiple bits are sent at the same time, each down its own wire — for example, a whole byte can be sent in one step using eight wires.

AdvantagesDisadvantages
Much faster than serial transmission, since many bits move at onceBits can arrive at very slightly different times over a longer wire, so the byte can become jumbled — this is called skew
Many computers move data this way internally (for example, between the processor and memory), so no conversion to serial is needed for that short journeyMultiple wires running next to each other are more likely to interfere with one another, increasing the chance of an error
More wires means a more expensive cable to manufacture and to buy

Because of skew and interference, parallel transmission is only reliable over very short distances — typically no more than about 5 metres — such as inside a computer.

Remember

Serial = one bit at a time, one wire, reliable over long distances. Parallel = many bits at a time, many wires, faster but only safe over short distances because of skew and interference.

Example: choosing between serial and parallel

A printing company connects a design computer to a large printer 3 metres away, and needs to print many leaflets quickly.

A parallel connection would be fast enough over this short distance, but it does carry a higher risk of skew and interference than a serial connection, and the cable is more expensive because of the extra wires. A serial connection would be more reliable but slower. In practice, an interface such as USB (Section 6) is often chosen here because it uses serial transmission at a high speed, giving good reliability without the cost and interference risk of a parallel cable.

Check yourself (5 questions)

  1. How many bits are transmitted at a time in serial transmission, and how many wires does it use?
    Answer
    One bit at a time, using a single wire.
  2. How many bits are transmitted at a time in parallel transmission?
    Answer
    Multiple bits at the same time, each down its own wire.
  3. What is meant by “skew”?
    Answer
    When bits sent at the same time (in parallel) arrive at slightly different times, so the data becomes jumbled/out of step.
  4. Give two advantages of serial transmission over parallel transmission.
    Answer
    Any two: less chance of the data being skewed; less chance of interference/errors; only one wire needed, so cheaper to manufacture and buy.
  5. A company transmits data between two devices 200 metres apart. Suggest, with a reason, whether serial or parallel transmission should be used.
    Answer
    Serial, because parallel transmission is only reliable over short distances (around 5 metres) due to skew and interference, while serial transmission remains reliable over long distances.

4. Simplex, half-duplex and full-duplex transmission

Syllabus objectives 2(a) and 2(b)

While serial and parallel describe how many bits move at once, simplex, half-duplex and full-duplex describe which direction(s) data can travel between two devices.

MethodDirection of dataExampleAdvantageDisadvantage
SimplexOne direction onlyA keyboard sending key presses to a computerSimple and cheap: only one direction of hardware is neededThe receiving device can never send anything back
Half-duplexBoth directions, but only one direction at a timeA pair of two-way radios (walkie-talkies)Both devices can send, using only one shared channel/wireDevices must take turns, so it is slower than full-duplex
Full-duplexBoth directions at the same timeA telephone callFastest form of two-way communication: no waiting for a turnNeeds more complex, more expensive hardware

A keyboard only ever needs to send data to the computer, not receive it, so a simplex connection is used. A telephone call needs both people to be able to speak and listen at the same time, so full-duplex is needed. Two-way radios can send in both directions, but only one person can transmit at any one moment, so half-duplex is used.

Remember

Ask two questions about a scenario. Does data ever need to travel back the other way? No → simplex. Yes → does it need to travel both ways at the exact same time? No, one direction at a time → half-duplex. Yes → full-duplex.

A connection always uses one option from each pair at once: for example, a connection can be a serial simplex connection, a parallel full-duplex connection, or a serial half-duplex connection. A full answer about a scenario should name one choice from each pair, with a reason linked to the scenario for each.

Example: a business and a file server

A business manager transmits customer data to a central file server 100 metres away. The manager needs to send and receive data to and from the server at the same time, and the accuracy of the data is very important.

The 100-metre distance rules out parallel transmission (too much skew and interference), so serial transmission should be used. Because data must travel in both directions at the same time, full-duplex transmission should be used.

Check yourself (5 questions)

  1. What is the difference between half-duplex and full-duplex transmission?
    Answer
    In half-duplex, data travels in both directions but only one direction at a time; in full-duplex, data travels in both directions at the same time.
  2. Give an example of a device connection that would use simplex transmission.
    Answer
    Any suitable example, such as a keyboard sending key presses to a computer, or a sensor sending readings to a computer, where data only ever needs to travel one way.
  3. State one advantage of simplex transmission.
    Answer
    It is simple and cheap, since hardware is only needed for one direction of data flow.
  4. State one disadvantage of half-duplex transmission compared with full-duplex.
    Answer
    Devices must take turns to send data (only one direction at a time), so it is slower than full-duplex.
  5. A weather station sensor only ever sends temperature readings to a display; the display never sends data back. Which method of direction of transmission is most suitable, and why?
    Answer
    Simplex, because data only ever needs to travel in one direction, from the sensor to the display, and the display never needs to send anything back.

5. Choosing a suitable transmission method

Syllabus objective 2(b)

Every connection between two devices actually needs two separate decisions: how many bits travel at a time (serial or parallel), and which direction(s) data can travel (simplex, half-duplex or full-duplex). Exam questions often describe a scenario and ask you to choose and justify one or both of these.

Three questions to ask about any scenario

  • How far apart are the devices? A short distance, such as inside a single device, makes parallel transmission safe. Anything longer favours serial transmission.
  • Does data ever need to travel back the other way? If not, simplex is enough. If it does, some form of duplex is needed.
  • Does data need to travel both ways at the same moment? If yes, full-duplex is needed. If the two directions can take turns, half-duplex is enough and is cheaper.
Remember

Distance decides serial vs parallel. Direction decides simplex vs half-duplex vs full-duplex. A complete answer names one choice from each pair and gives a reason for each, using details from the scenario.

Common mistakes

Giving a method with no reason (“Serial” alone earns nothing without a linked justification). Choosing parallel for anything outside a single device or a very short cable. Choosing full-duplex just because data flows both ways, without checking whether it needs to happen at the same time.

Worked example

A ticket kiosk at a ferry terminal is connected to a ticket printer by a cable. The kiosk sends ticket data to the printer, and the printer sends status messages back to the kiosk, but never at the exact same moment.

Step 1 — distance: the kiosk and printer are separate devices connected by a cable, so this is a longer distance than “inside one device” → serial transmission avoids skew and interference over this distance.

Step 2 — direction: data needs to travel both ways (ticket data one way, status messages the other), so simplex is ruled out. Since the question says this never happens at the same moment → half-duplex transmission is suitable.

Full answer: Serial, half-duplex transmission. Serial is used because the distance between the kiosk and the printer would cause skew and interference with a parallel connection. Half-duplex is used because data must travel in both directions, but never at the same time.

Check yourself (5 questions)

  1. What two separate choices need to be made for any data transmission connection?
    Answer
    How many bits are sent at a time (serial or parallel), and which direction(s) data can travel (simplex, half-duplex or full-duplex).
  2. Which factor mainly decides whether serial or parallel transmission should be used?
    Answer
    The distance between the two devices (parallel is only suitable over very short distances).
  3. A sensor sends data to a controller over a long wire and never receives any data back. State a suitable method for the number of bits transmitted at a time, and a suitable direction of transmission.
    Answer
    Serial (long distance rules out parallel), simplex (data only ever travels one way).
  4. Data moves between the processor and memory inside a computer, in both directions, at the same time. Suggest suitable methods, with reasons.
    Answer
    Parallel, because the distance is very short so skew and interference are not a problem, and it is faster; full-duplex, because data must travel in both directions at the same time.
  5. Why does a full scenario answer need to name a method AND a reason for each of the two choices?
    Answer
    Because a method on its own could be correct by chance; the reason, linked to details in the scenario such as distance or the direction data needs to flow, is what shows understanding and earns the marks.

6. The universal serial bus (USB) interface

Syllabus objective 3

The universal serial bus (USB) is a widely used standard interface for connecting devices, such as keyboards, mice, printers, cameras, phones and flash drives, to a computer. As its name says, USB uses serial transmission: data travels one bit at a time.

How USB transmits data

  • The device is plugged into a USB port, and the computer automatically detects the device.
  • The computer identifies the type of device and loads the correct device driver, so that the computer and the device can communicate. If a suitable driver is not already available, the user may be asked to install one.
  • Data is then transmitted serially between the device and the computer.
  • The USB cable can also supply power to the device, so a small device does not always need its own separate power supply.

Benefits and drawbacks of the USB interface

BenefitsDrawbacks
The connector only fits one way, so it is difficult to connect a device incorrectlyA USB cable only works reliably over a limited length (commonly around 5 metres); the signal weakens over longer distances
The device is detected automatically and its driver is loaded automatically, so little technical knowledge is needed to use itThe transmission speed is limited by the USB standard being used; older standards (such as USB 1 or 2) are much slower than newer ones
USB is a universal, widely supported standard, so a USB port is included on many different kinds of deviceOlder USB ports and cables may not support the fastest speeds of newer devices, so the connection may run slower than the device is capable of
The cable can also supply power to the connected device, so some devices need no separate power source
Example: a flash drive

A student plugs a flash drive into their laptop. The laptop automatically detects the flash drive and loads the correct driver, so files can immediately be copied to it. Because USB is a universal standard, the same flash drive will also work when plugged into almost any other computer, and because the transmission is serial, it remains reliable even though the cable is a few metres long.

Check yourself (5 questions)

  1. What type of data transmission does the USB interface use?
    Answer
    Serial transmission.
  2. Describe what happens when a USB device is first connected to a computer.
    Answer
    The computer automatically detects the device, and the correct device driver is loaded (automatically, or the user is asked to install one) so the two can communicate.
  3. Give two benefits of using the USB interface.
    Answer
    Any two: automatic detection and automatic driver loading (little technical knowledge needed); the connector only fits one way, so it is hard to connect incorrectly; it is a universal standard supported by many devices; it can supply power to the connected device.
  4. Give two drawbacks of using the USB interface.
    Answer
    Any two: the cable only works reliably over a limited length; transmission speed is limited by the USB standard being used; an older port or cable may not support a newer, faster device at full speed.
  5. Why is a USB connection able to transmit data reliably even though it is serial, which is normally slower than parallel?
    Answer
    USB is a special, high-speed form of serial transmission, designed to transmit data quickly while keeping the reliability advantages of serial transmission (no skew, less interference).

2.2 Methods of error detection

Why transmission errors happen, and five ways to detect them: parity check, checksum, echo check, ARQ, and check digit.

1. Why errors occur, and the need for error detection

Syllabus objective 1

Transmitting data from one device to another is not always a perfect process. As data travels along a wire, through a cable, or over a wireless signal, interference (electrical noise from nearby devices and cables) can disturb it. This can cause:

  • Data loss — a bit that was sent does not arrive; it is simply lost.
  • Data gain — an extra bit appears in the received data that was never sent.
  • Data change — a bit arrives with the wrong value: a 1 becomes a 0, or a 0 becomes a 1.

These errors matter. If a password, an address, or a payment amount is not transmitted correctly, the consequences can be serious: a person may not be able to log in, a message may go to the wrong place, or a transaction may be wrong. Because of this, systems need a reliable way to check for errors after data has been transmitted, so that corrupted data can be identified and, where possible, corrected by requesting it again.

Remember

Interference is the general cause of transmission errors, and it can lead to three effects: data loss, data gain, and data change. Error detection methods check whether the data that arrived matches the data that was sent.

An overview of the error detection methods

Cambridge 0478 requires five error detection methods. Four of them check for errors that occurred during transmission; one of them (the check digit) checks for errors made when data is entered or scanned.

MethodWhat it checks forWhen it is used
Parity checkTransmission errorsAfter transmission
ChecksumTransmission errorsAfter transmission
Echo checkTransmission errorsAfter transmission
Automatic repeat request (ARQ)Transmission errors, and triggers a resendAfter transmission
Check digitData entry errors (typing or scanning)When data is entered
Exam tip

If a question specifically asks for a method used to check data after transmission, a check digit is not a valid answer, because it checks data entry, not transmission.

Check yourself (5 questions)

  1. What is the general cause of errors in data transmission?
    Answer
    Interference (electrical noise) affecting the wire, cable or wireless signal used to transmit the data.
  2. Name the three effects interference can have on transmitted data.
    Answer
    Data loss, data gain, and data change.
  3. Why is it important to check for errors after data has been transmitted?
    Answer
    Because incorrect data (such as a password, address or payment amount) can cause serious problems, so systems need to detect when data has been corrupted and, if possible, have it resent.
  4. Name the five error detection methods required for this syllabus.
    Answer
    Parity check, checksum, echo check, automatic repeat request (ARQ), and check digit.
  5. Which of the five error detection methods checks for errors in data entry rather than data transmission?
    Answer
    The check digit.

2. Parity check

Syllabus objective 2

A parity check detects errors by counting the number of 1s in a byte of data. Before data is transmitted, an extra bit called the parity bit is added to each byte. It is set so that the total number of 1s in the byte (data bits plus the parity bit) is either always odd (odd parity) or always even (even parity), whichever has been agreed before transmission.

Position76543210
Place valuePb7b6b5b4b3b2b1

How a parity check works, step by step

  1. Before transmission, the sender and receiver agree whether odd or even parity will be used.
  2. For each byte, the sender counts the number of 1s in the 7 data bits.
  3. The sender sets the parity bit so that the total number of 1s (data bits plus parity bit) matches the agreed parity.
  4. The full byte (7 data bits plus the parity bit) is transmitted.
  5. After transmission, the receiver counts the number of 1s in all 8 received bits.
  6. If the total matches the agreed parity, no error is detected. If it does not match, an error has been detected.
Remember

Even parity: the parity bit is set so the total number of 1s in the byte is even. Odd parity: the parity bit is set so the total number of 1s in the byte is odd.

Worked example: setting and checking a parity bit

The 7 data bits 1 0 1 1 0 1 0 are to be sent using even parity.

Step 1 — count the 1s: 1, 0, 1, 1, 0, 1, 0 → there are 4 ones.

Step 2 — set the parity bit: 4 is already even, so the parity bit is set to 0 to keep the total even.

P  b7 b6 b5 b4 b3 b2 b1
0  1  0  1  1  0  1  0     total 1s = 4 (even) ✓

Step 3 — the receiver checks: after transmission, the receiver counts the 1s in all 8 bits it received. If the total is even, no error is detected. If the total is odd, an error has occurred.

Try it: build a byte and break it

Click the 7 data bits to set them. The parity bit (P) is calculated for you. Then flip one bit, or two, to see what the receiver notices.

A limitation of the parity check

A parity check only detects an odd number of changed bits (1, 3, 5…). If exactly two bits in the same byte are flipped during transmission, the total count of 1s returns to what it should be, and the error is missed completely.

Parity byte and parity block check

A single parity bit can only tell you that an error occurred somewhere in one byte, not which bit. When a whole block of many bytes is sent together, a parity block check is used, which can pinpoint the exact bit that changed.

  • Each byte in the block already has its own parity bit, calculated as above. This is a check along each row.
  • After all the bytes, an extra byte called the parity byte is calculated and sent. Each bit of the parity byte is the parity bit for one column: look down that bit position through every byte in the block, and set the parity byte’s bit for that position so the column also matches the agreed parity.
  • This gives a check along each column as well as along each row.
Worked example: parity block check (even parity)

A block of 4 bytes is to be transmitted using even parity.

Byte     b7 b6 b5 b4 b3 b2 b1   1s in data   Parity bit (P)
Byte 1   1  1  0  0  1  0  1     4            0
Byte 2   0  1  1  0  1  0  0     3            1
Byte 3   1  0  0  1  1  1  0     4            0
Byte 4   0  0  1  1  0  1  1     4            0

Each row parity bit is set so that row’s total number of 1s (including P) is even — for example, Byte 2 has 3 ones in its data bits, so P = 1 to make the row total 4.

Now find the parity byte, one column at a time. Look down each column (including the P column) across all 4 bytes and count the 1s:

Column        P   b7  b6  b5  b4  b3  b2  b1
Byte 1        0   1   1   0   0   1   0   1
Byte 2        1   0   1   1   0   1   0   0
Byte 3        0   1   0   0   1   1   1   0
Byte 4        0   0   0   1   1   0   1   1
Column total  1   2   2   2   2   3   2   2

Parity byte:  1   0   0   0   0   1   0   0

Every column already has an even total except the P column (1 one) and the b3 column (3 ones), so the parity byte has a 1 in those two positions and 0 everywhere else: parity byte = 1 0 0 0 0 1 0 0.

If a single bit is corrupted during transmission — say, bit b5 of Byte 3 flips from 0 to 1 — Byte 3’s own row will no longer match even parity, and the b5 column will no longer match the parity byte either. The row and the column that both fail cross at exactly the bit that changed, so the receiver can identify, and in this case correct, that one bit.

Exam tip

Describe a parity block check as two checks working together: a row check (each byte’s own parity bit) and a column check (the parity byte). A single-bit error makes exactly one row and one column fail, and where they cross is the corrupted bit.

  1. What is a parity bit?
    Answer
    An extra bit added to a byte of data, set so that the total number of 1s in the byte matches an agreed odd or even parity.
  2. The 7 data bits 1 1 0 0 1 0 0 are to be sent using odd parity. State the parity bit that should be added.
    Answer
    The data bits contain 3 ones, which is already odd, so the parity bit is set to 0 to keep the total odd (3).
  3. A byte is received as 0 1 1 0 0 1 0 0 and even parity is being used. Does the receiver detect an error? Explain.
    Answer
    The received byte contains 3 ones, which is odd, not even. Since even parity was agreed, this does not match, so an error is detected.
  4. Explain one limitation of a simple parity check.
    Answer
    It can only detect an odd number of changed bits; if exactly two bits in the same byte are flipped, the count of 1s is unchanged and the error is not detected.
  5. In a parity block check, what does a single failing row and a single failing column together tell the receiver?
    Answer
    They identify the exact bit that has been corrupted, since the failing row and the failing column cross at that one bit position.

3. Checksum

Syllabus objective 2

A checksum is a value calculated from a set of data using an algorithm, and is used to check whether that data has changed during transmission.

How it works, step by step

  1. Before transmission, the sender runs the data through an agreed algorithm to calculate a checksum value.
  2. The checksum value is transmitted along with the data, not instead of it.
  3. After transmission, the receiver runs the same algorithm on the data it received, producing its own checksum value.
  4. The receiver compares the checksum value it calculated with the one that was transmitted.
  5. If the two values match, no error is detected. If they do not match, an error has occurred, and the data can be requested again.
Remember

A checksum is calculated → transmitted with the data → recalculated by the receiver → compared. Because both sides use the same algorithm, different results can only mean the data itself was different, so it must have changed during transmission.

Exam tip

Do not say the checksum is “added to” the data as though it becomes part of it; say it is transmitted along with the data. Also state clearly that the receiver uses the same algorithm to recalculate the value — this is often a separate marking point.

Example

A weather station transmits five sensor readings to a control centre. Before sending, it calculates a checksum from the five values and transmits it along with them. At the control centre, the same calculation is performed on the received readings. If its checksum matches the one that was sent, the readings are accepted as correct; if not, the control centre asks for the readings to be sent again.

Check yourself (5 questions)

  1. What is a checksum?
    Answer
    A value calculated from a set of data using an algorithm, used to check whether the data has changed during transmission.
  2. Describe what happens to the checksum value before the data is transmitted.
    Answer
    It is calculated from the data using an algorithm, and is transmitted along with the data.
  3. What does the receiver do with the checksum value after the data has been transmitted?
    Answer
    It recalculates a checksum value from the received data, using the same algorithm, and compares it with the checksum value that was transmitted.
  4. Why does a mismatch between the two checksum values show that an error has occurred?
    Answer
    Because both sides use the same algorithm on the data; if the results are different, the data used to calculate them must have been different, meaning it changed during transmission.
  5. Name one other error detection method (besides checksum) that can be used to check for errors after transmission.
    Answer
    Any one of: parity check, echo check, automatic repeat request (ARQ).

4. Echo check

Syllabus objective 2

An echo check detects errors by comparing the data before and after it has made a round trip, rather than by calculating a value.

How it works, step by step

  1. The sending device transmits data to the receiving device.
  2. The receiving device transmits a copy of the data it received straight back to the sender.
  3. The sending device compares the data it originally sent with the copy it has received back.
  4. If the two match, no error has occurred. If they do not match, an error has occurred, and the data can be requested again.
Sender  ───── data ─────────────────►  Receiver
Sender  ◄──── copy of received data ───  Receiver

Sender compares: data it sent vs copy received back
Match → no error          Do not match → error detected
Remember

Echo check = data sent → a copy sent back → sender compares original with copy. Unlike a parity check or checksum, it uses no calculated value at all, only a direct comparison.

A limitation of the echo check

If the sender and the copy do not match, the sender knows an error occurred somewhere, but not whether it happened on the journey to the receiver or on the copy’s journey back. Either direction of the round trip could be the cause.

Example

A student sends a file from their laptop to a school printer. The printer sends a copy of the data it received back to the laptop. The laptop compares the data it originally sent with the copy that has come back from the printer. If they match, the laptop assumes the file was received correctly; if they do not match, an error has occurred somewhere during the round trip, and the laptop sends the file again.

Check yourself (5 questions)

  1. Describe the three steps of an echo check.
    Answer
    The sender transmits data to the receiver; the receiver sends a copy of the received data back to the sender; the sender compares the original data it sent with the copy it received back.
  2. How does the sender know an error has occurred, using an echo check?
    Answer
    If the data it originally sent does not match the copy it receives back, an error has occurred.
  3. Does an echo check use a calculated value, such as a checksum? Explain.
    Answer
    No. It works by directly comparing the original data with a copy sent back, with no algorithm or calculation involved.
  4. Give one limitation of the echo check.
    Answer
    If the comparison fails, the sender cannot tell whether the error happened on the way to the receiver or on the copy’s way back — only that an error occurred somewhere.
  5. An echo check is used between a computer and a scanner. Describe how it detects an error.
    Answer
    The computer sends data to the scanner; the scanner sends a copy of the received data back to the computer; the computer compares the data it sent with the copy received back, and if they do not match, an error has occurred.

5. Automatic repeat request (ARQ)

Syllabus objective 4

An automatic repeat request (ARQ) is a method used to make sure that data is received without error, by combining acknowledgements with a timer, and automatically resending data when something goes wrong.

Positive acknowledgement ARQ

  1. The sending device transmits a data packet and starts a timer.
  2. The receiving device checks the packet for errors.
  3. If the packet is error-free, the receiver sends a positive acknowledgement back to the sender.
  4. When the sender receives the positive acknowledgement, it resets the timer and sends the next packet.
  5. If the sender does not receive an acknowledgement before the timer runs out, a timeout occurs, and the sender resends the same packet.
  6. This continues until a positive acknowledgement is received, or until a set maximum number of attempts has been reached.

Negative acknowledgement ARQ

  1. The sending device transmits a data packet.
  2. The receiving device checks the packet for errors.
  3. If the receiver detects an error, it sends a negative acknowledgement back to the sender, and the sender resends that packet.
  4. If no error is detected, no acknowledgement (or only a brief confirmation) is sent, and the sender still sets a timeout so that it does not wait forever for a negative acknowledgement that will never come.
Remember

Both versions of ARQ use a timer/timeout and an acknowledgement. The difference is what triggers the resend: with a positive acknowledgement, no message within the timeout means resend; with a negative acknowledgement, receiving that specific message means resend.

Exam tip

A question may combine ARQ with another method, such as a parity check, in one scenario (for example, “describe how this combined system checks for errors”, worth many marks). Cover both parts in order: how the transmission-level check (such as parity) is performed, then how ARQ uses acknowledgements and timeouts to trigger a resend.

Example: positive acknowledgement ARQ

A file is sent in five packets using positive acknowledgement ARQ. The sender transmits packet 1 and starts a timer. The receiver checks packet 1, finds no errors, and sends back a positive acknowledgement. The sender receives this before the timer runs out, so it sends packet 2 and restarts the timer. Packet 3 is lost during transmission, so no acknowledgement arrives before the timer ends: a timeout occurs, and the sender resends packet 3. This continues until all five packets have been positively acknowledged.

Check yourself (5 questions)

  1. What two things does an ARQ system rely on to check that data has arrived correctly?
    Answer
    Acknowledgements (sent back by the receiver) and a timer/timeout.
  2. Describe what happens in positive acknowledgement ARQ when the receiver finds no errors in a packet.
    Answer
    The receiver sends a positive acknowledgement back to the sender, which then resets its timer and sends the next packet.
  3. What is a timeout, and what happens when one occurs?
    Answer
    A timeout is when the sender’s timer runs out before it receives an acknowledgement; when this happens, the sender resends the data packet.
  4. In negative acknowledgement ARQ, what causes the sender to resend a packet?
    Answer
    Receiving a negative acknowledgement from the receiver, which is sent when the receiver detects an error in that packet.
  5. A packet is transmitted correctly, but the positive acknowledgement sent back is lost. What is likely to happen, and why?
    Answer
    The sender’s timer runs out without an acknowledgement being received, so a timeout occurs and the sender resends the packet, even though the original copy actually arrived correctly (so the receiver may end up with a duplicate).

6. Check digit

Syllabus objective 3

A check digit is a single digit calculated from the other digits in a number, and added onto the end of that number. Unlike the other four methods in this topic, a check digit does not check for errors during transmission — it checks for errors made when data is entered, whether typed in by hand or read automatically, for example by a barcode scanner.

How it works, step by step

  1. A check digit is calculated from the other digits of a number (for example, a barcode number or an ISBN), using an agreed algorithm, and is stored as the final digit of that number.
  2. When the number is entered — typed in, or scanned — the check digit is recalculated from the digits that were entered, using the same algorithm.
  3. If the recalculated check digit matches the one stored in the number, the data entered is accepted as correct.
  4. If it does not match, an error has occurred during data entry.
Remember

Check digit = calculated → added to the number → recalculated at entry → compared. It is easy to confuse a check digit with a checksum, because the process sounds similar. The difference is when the error can happen: a checksum checks for errors during transmission; a check digit checks for errors during data entry (typing or scanning).

Where check digits are used

  • International Standard Book Numbers (ISBN) — every published book has a unique ISBN, and its final digit is a check digit calculated from the digits before it, to catch a mistyped or mis-scanned ISBN.
  • Barcodes — a barcode printed on a product includes a check digit as part of its number. When a checkout scanner reads the barcode, the check digit is recalculated to confirm the barcode was scanned correctly.
Exam tip

Cambridge does not ask you to actually calculate a real check digit — only to describe the process (calculated, added, recalculated on entry, compared) and to give examples of where check digits are used, such as ISBNs and barcodes.

Example

A supermarket checkout scans a product’s barcode. The check digit stored in the barcode was originally calculated from the other digits of the barcode number. When the scanner reads the barcode, it recalculates the check digit from the digits it has just scanned, using the same method. If the recalculated check digit matches the one printed in the barcode, the scan is accepted; if it does not match — perhaps because the barcode was smudged or misread — the till rejects the scan and asks for the product to be scanned again.

Check yourself (5 questions)

  1. What is a check digit?
    Answer
    A single digit calculated from the other digits in a number and added to the end of it, used to detect errors made when the number is entered.
  2. Does a check digit detect errors in transmission or in data entry?
    Answer
    Data entry (typing in a number, or scanning it) — not transmission.
  3. Describe what happens when a number with a check digit is entered or scanned.
    Answer
    The check digit is recalculated from the digits that were entered, using the same algorithm that produced the original check digit, and the two are compared.
  4. Give two examples of where a check digit is used.
    Answer
    International Standard Book Numbers (ISBNs) and barcodes.
  5. Explain the key difference between a check digit and a checksum.
    Answer
    Both are calculated values that are recalculated and compared, but a checksum checks for errors that occur during transmission of data, while a check digit checks for errors made when data is entered (typed or scanned) rather than during transmission.

2.3 Encryption

Why data is encrypted, the plaintext/key/ciphertext model, and symmetric versus asymmetric encryption.

1. Why data is encrypted: plaintext, key and ciphertext

Syllabus objective 1

Data that travels across a network passes through cables, routers and wireless signals that are not owned or controlled by the sender or receiver. Anyone with the right equipment along that path could copy the data as it goes past. Encryption is used to protect data from being understood if this happens.

What encryption does and does not do

Encryption does not stop data being intercepted — an eavesdropper can still capture it. What encryption does is make any intercepted data meaningless: without the correct key, it cannot be understood or used.

Plaintext, key and ciphertext

  • Plaintext — the original, readable data, before it has been encrypted.
  • Key — a value used, together with an encryption algorithm, to scramble the plaintext. A matching key is needed to unscramble it again.
  • Ciphertext — the scrambled, meaningless data produced by encryption. This is the form of the data that is actually transmitted.
Plaintext ── encrypted using a key ──► Ciphertext ── transmitted ──► Ciphertext
                                                                        │
                                                        decrypted using a key
                                                                        ▼
                                                                    Plaintext
Exam tip

The single most common way to lose marks on this topic is writing that encryption “stops data being intercepted” or “stops hackers accessing the data”. The correct wording is that the data can still be intercepted, but it is meaningless / cannot be understood without the key.

Example

A person logs into a banking app. Their password (the plaintext) is encrypted using a key, producing ciphertext, which is transmitted to the bank’s server. If this ciphertext were intercepted while it travelled across the network, it would appear as meaningless scrambled data to whoever intercepted it, because they do not have the correct key to decrypt it. At the server, the same or a matching key is used to decrypt the ciphertext back into the original plaintext password.

Check yourself (5 questions)

  1. What is the purpose of encrypting data before it is transmitted?
    Answer
    So that if the data is intercepted during transmission, it cannot be understood (it is meaningless) without the correct key.
  2. Does encryption prevent data from being intercepted? Explain.
    Answer
    No. Data can still be intercepted; encryption only makes the intercepted data meaningless to anyone without the correct key.
  3. Define the terms plaintext and ciphertext.
    Answer
    Plaintext is the original, readable data before encryption. Ciphertext is the scrambled, meaningless data produced by encrypting the plaintext.
  4. What is a key used for in encryption?
    Answer
    It is used, together with an algorithm, to scramble plaintext into ciphertext, and a matching key is used to unscramble the ciphertext back into plaintext.
  5. A message is encrypted before being sent over the internet. Using the terms plaintext, key and ciphertext, describe what happens to it.
    Answer
    The plaintext message is encrypted using a key, producing ciphertext; the ciphertext is transmitted; the receiver uses a key to decrypt the ciphertext back into the original plaintext.

2. Symmetric encryption

Syllabus objective 2

In symmetric encryption, the same key is used to both encrypt and decrypt the data.

How it works, step by step

  1. The sender and the receiver both hold an identical copy of a secret key.
  2. The sender encrypts the plaintext using the key, producing ciphertext.
  3. The ciphertext is transmitted across the network.
  4. The receiver decrypts the ciphertext using the same key, recovering the original plaintext.

The key exchange problem

Before any of this can happen, both sides must somehow already hold the same secret key. If that key itself has to be sent across the network and it is intercepted on the way, whoever intercepts it can then decrypt everything encrypted with it. This weakness is called the key exchange (or key distribution) problem, and it is the main drawback of symmetric encryption.

AdvantagesDisadvantages
Fast: encrypting and decrypting need relatively little processing, so it suits large amounts of dataThe key must be exchanged between the sender and receiver; if it is intercepted during that exchange, the encryption is broken
Simple: only one key needs to be generated, stored and usedEvery pair of people who need to communicate securely needs its own shared key, which becomes difficult to manage as the number of users grows
Remember

Symmetric = the SAME key encrypts and decrypts. Its strength is speed; its weakness is that the key has to be shared somehow, and could be intercepted during that exchange.

Example

A courier company uses symmetric encryption to transmit tracking data between two of its offices. Both offices hold an identical copy of the same key. The sending office encrypts the plaintext tracking data using the key, producing ciphertext, which is transmitted to the other office. The receiving office decrypts the ciphertext using its identical copy of the same key, recovering the original plaintext data.

Check yourself (5 questions)

  1. In symmetric encryption, how many keys are used, and by whom?
    Answer
    One key, and the same key is used by both the sender (to encrypt) and the receiver (to decrypt).
  2. Describe the process of symmetric encryption.
    Answer
    The sender and receiver hold an identical key; the sender encrypts the plaintext using the key to produce ciphertext, which is transmitted; the receiver decrypts the ciphertext using the same key to recover the plaintext.
  3. What is the “key exchange problem”?
    Answer
    The key itself has to be given to the receiver somehow; if it is intercepted during this exchange, whoever intercepts it can decrypt all data encrypted with that key.
  4. Give one advantage of symmetric encryption.
    Answer
    It is fast / needs relatively little processing, so it is suitable for encrypting large amounts of data.
  5. Explain one drawback of using symmetric encryption to transmit sensitive data.
    Answer
    The same key must be exchanged between sender and receiver before it can be used; if that key is intercepted during the exchange, the interceptor can then decrypt all the data sent using that key.

3. Asymmetric encryption

Syllabus objective 2

In asymmetric encryption, two different keys are used as a matching pair: a public key and a private key.

  • The public key is shared openly with anyone, and is used to encrypt data.
  • The private key is kept secret by its owner and is never shared or transmitted. It is the only key that can decrypt data that was encrypted with the matching public key.

How it works, step by step

  1. The receiver generates a matching pair of keys: one public, one private.
  2. The receiver shares their public key openly; anyone who wants to send them data securely obtains a copy of it.
  3. The sender encrypts the plaintext using the receiver’s public key, producing ciphertext.
  4. The ciphertext is transmitted. Even someone who intercepts it, and who also has a copy of the public key, cannot decrypt it, because the public key can only encrypt, not decrypt.
  5. The receiver decrypts the ciphertext using their own private key, recovering the plaintext.
Remember

Asymmetric = TWO keys, a matching pair. The receiver’s public key encrypts; the receiver’s private key decrypts. The private key is never shared, so there is no key exchange problem.

Symmetric compared with asymmetric encryption

SymmetricAsymmetric
Keys usedOne key: the same key encrypts and decryptsTwo keys: a public key encrypts, the matching private key decrypts
Key sharingThe key must be exchanged, so there is a risk of interceptionOnly the public key is shared; the private key is never transmitted
SpeedFaster, needs less processingSlower, needs more processing
A common mistake

It is easy to muddle up which key does which job. Fix this rule in your memory: the receiver’s public key encrypts; the receiver’s private key decrypts. Both keys belong to the receiver — the sender does not generate any keys.

Example

A customer buys a concert ticket online. The website’s server has a matching pair of keys: a public key, shared openly, and a private key, kept secret. The customer’s browser encrypts their plaintext payment details using the server’s public key, producing ciphertext, which is transmitted. Even if this ciphertext were intercepted, along with a copy of the public key, it could not be decrypted, because only the server’s private key — which is never shared — can decrypt data encrypted with that public key. The server uses its private key to decrypt the ciphertext and recover the plaintext payment details.

Check yourself (5 questions)

  1. How many keys are used in asymmetric encryption, and what are they called?
    Answer
    Two keys: a public key and a private key.
  2. Which key is used to encrypt data in asymmetric encryption, and who can access it?
    Answer
    The receiver’s public key, which is shared openly and can be obtained by anyone.
  3. Which key is used to decrypt data in asymmetric encryption, and who can access it?
    Answer
    The receiver’s private key, which is kept secret by the receiver and never shared or transmitted.
  4. Why does asymmetric encryption not have a “key exchange problem” like symmetric encryption does?
    Answer
    Because the private key, which is needed to decrypt the data, is never shared or transmitted; only the public key (which can only encrypt) is shared, so intercepting it does not allow the data to be decrypted.
  5. Give one difference between symmetric and asymmetric encryption.
    Answer
    Any one: symmetric uses one key for both encrypting and decrypting, while asymmetric uses two different keys (public to encrypt, private to decrypt); or, symmetric is faster than asymmetric because it needs less processing.

Question 6 Parity check[6]

  1. (a)The 7 data bits 1 0 0 1 0 1 1 are to be transmitted using even parity. State the parity bit that should be added.[2]

(b) Any one: an echo check does not use a calculated value, it compares the original data sent with a copy sent back, whereas a checksum uses a value calculated by an algorithm; or, an echo check cannot show which direction of the round trip the error happened in, while a checksum only checks the one-way transmission.

Question 8 Automatic repeat request (ARQ)[6]

  1. (a)An ARQ system uses a positive acknowledgement method. Explain how this ARQ system operates.[5]
  2. (b)State what is used, in an ARQ system, to trigger the sender to resend a packet when no acknowledgement is received.[1]
Mark scheme

(a) Any five [1 each]: a timer is started when the sender transmits a data packet; the receiver checks the packet for errors; if the packet is error-free, the receiver sends a positive acknowledgement back to the sender; the sender resets the timer and sends the next packet; if no acknowledgement is received before the timer runs out, a timeout occurs and the packet is resent.

(b) A timeout [1].

Question 9 Check digit[4]

  1. (a)A library types in a book’s ISBN to check it out. Describe how a check digit is used to detect an error in this process.[3]
  2. (b)State one other example, besides ISBNs, of where a check digit is used.[1]
Mark scheme

(a) The check digit was calculated from the ISBN’s other digits using an algorithm, when the ISBN was first created [1]; when the ISBN is typed in, the check digit is recalculated from the digits entered, using the same algorithm [1]; if the recalculated check digit does not match the one stored in the ISBN, a data entry error has occurred [1].

(b) Barcodes [1].

Question 10 Encryption[8]

  1. (a)Explain the purpose of encrypting data before it is transmitted.[2]
  2. (b)Describe how symmetric encryption is used to transmit data.[3]
  3. (c)Describe how asymmetric encryption is used to transmit data, naming the keys used at each step.[3]
Mark scheme

(a) The data is scrambled so it cannot be understood [1]; so that if it is intercepted during transmission, it is meaningless to the interceptor, who does not have the key to decrypt it [1]. (Do not accept: it prevents the data from being intercepted.)

(b) Any three: the sender and receiver hold an identical (the same) key; the sender encrypts the plaintext with the key, producing ciphertext, which is transmitted; the receiver decrypts the ciphertext using the same key, recovering the plaintext.

(c) Any three: the receiver has a matching pair of keys, a public key and a private key; the sender encrypts the plaintext using the receiver’s public key, producing ciphertext, which is transmitted; the receiver decrypts the ciphertext using their own private key (which is never shared), recovering the plaintext.
