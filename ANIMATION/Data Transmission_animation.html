See how data travels

Every photo you send, every video call and every web page is data moving from one device to another. That movement is called data transmission. Here you will watch it happen, break it on purpose, then fix it.

A computer cannot send a whole photo as one lump. It sends it as tiny pieces called packets. Each packet has three parts: a header (the address label), a payload (the real data) and a trailer (the end marker). You meet them in lesson 1.

Serial and parallel

Watch: Data transmission methods▶ Full videoSerial vs parallelSkew
In plain words: serial is children walking through one door, one by one. Parallel is eight children walking through eight doors at the same time. Eight doors is faster, but on a long road some children walk faster than others and arrive mixed up.

One byte: 10110010

Press a button.
Serial
1 wire, bits one after another. Cheaper, no skew, good over long distance. Used by USB.
Parallel
Many wires, many bits at once. Faster over short distance. Over long distance the bits can arrive at different times (skew) and the wires can interfere with each other.
Exam tip: compare both methods on distance, speed, cost and errors. Say "skew" and "more wires" for parallel.

USB

Watch: Universal Serial Bus (USB)▶ Full videoBenefitsDrawbacks
In plain words: USB is one standard plug and socket that nearly every gadget agrees on, so you can plug in a mouse, a phone or a flash drive and the computer says hello by itself.

USB sends data serially, one bit after another, down the cable.

Benefits
Standard connector on many devices. Device is detected automatically. Can also power the device. Newer versions work with older ones (backward compatible). Fast enough for most jobs.
Drawbacks
Cable length is limited, so it suits short distances. Transfer speed is lower than some other connections. A device only works if the right USB version and connector exist.
Exam tip: "serial", "standard connector", "automatic detection", and for drawbacks "limited cable length" and "limited speed".

Errors and parity check

Watch: Error detection methods▶ Full videoParity checksParity block
In plain words: data can get lost, gained or changed on the road (electrical noise, interference). Parity is a spy that counts the 1s. Before sending we agree: the total number of 1s must be even (or odd). If the count is wrong on arrival, something changed.
Rule: Tap a data bit to flip it.

2D parity: find the damaged bit

Every row and column has an even parity bit (amber). Tap a data bit to damage it, or start a challenge.

Exam tip: count the 1s, set the parity bit so the total is even (or odd). A parity block checks rows and columns to find exactly which bit is wrong. Weakness: two flipped bits cancel out and parity misses them.

Checksum

Add up all the data and send the total too. The receiver adds again. Different totals mean damage.
Sent data: Received data:

Echo check

Shout it, and ask the friend to shout it back. If it comes back different, it broke.

Check digit (ISBN-13)

The last digit is a secret calculated from the others. Change one digit and the sum breaks. Weights alternate 1, 3, 1, 3 ... and the total must end in 0.

ARQ (automatic repeat query)

The receiver replies "Got it" (positive acknowledgement) or "Broken, send again" (negative acknowledgement). If no reply comes before the timer runs out, the sender simply sends again.
Exam tip: checksum: "value calculated from the data using an algorithm, sent with the data, recalculated at the other end". Echo: "copy of the data sent back to the sender". ARQ: "acknowledgement and timeout, resend until acknowledged or limit reached".
